# אלרגן

מאגר וסינון אלרגנים למוצרי מזון ארוזים מראש הנמכרים בישראל.

הרעיון פשוט וההנדסה סביבו לא: לתת לאדם עם אלרגיה לסנן מוצרים לפי מה שהם
מכילים ולפי מה שהם עלולים להכיל, ולסרוק ברקוד מול המדף ולקבל תשובה גם בלי
קליטה. מה שמסבך הוא שהמידע מפוזר בין מקורות שאף אחד מהם אינו שלם, והמחיר
של טעות בכיוון אחד גבוה בהרבה מהמחיר של טעות בכיוון השני.

## שלושה כללים שמסבירים את רוב הקוד

**1. האפליקציה לעולם לא אומרת שמוצר בטוח.** היא מסתירה מה שידוע כמסוכן
ומתעדת מה שידוע. המילים "בטוח", "נקי" ו"ללא" אינן בשימוש כתיאור של מוצר,
אין ירוק בשום מקום, ו"אין מידע" הוא מצב שלישי מלא ומוצג — לעולם לא
"לא מכיל".

**2. מקור שאינו יצרן יכול רק להוסיף אלרגן, לעולם לא לשלול.**
[ADR-0002](docs/adr/0002-extraction-can-add-never-clear.md)

**3. כישלון או שתיקה של מקור לא מחזירים מוצר למצב אין מידע.** הכלל הזה
הוכיח את עצמו: בריצה שבה 83 אחוז מהבקשות ל-Open Food Facts נכשלו, אף
מוצר לא נרשם בטעות כחסר אלרגנים.

## מצב הנתונים, כפי שנמדד

המספרים כאן הם תוצאה של ריצות אמיתיות מול המקורות, לא הערכות.

| מדד | ערך |
|---|---|
| מוצרים בקטלוג (5 סניפי שופרסל) | 8,728 |
| גודל תמונת המצב | 2.8MB |
| סיווג למחלקות | 68% מסווגים, 32% לא מסווגים |
| פריטים שאינם מזון | 697 (מסומנים, לא נמחקים) |
| נמצאו ב-Open Food Facts | 580 מתוך 1,493 שנשאלו (39%) |
| מהם עם תגיות אלרגנים | 89 (6% מהנשאלים) |
| דפי יצרן שנקראו | 8, כולם קושרו לברקוד ודאי |

**כיסוי האלרגנים נמוך, וזו העובדה המרכזית על גרסה 1.** Open Food Facts
מכיר פחות מארבעים אחוז מהמוצרים שנמכרים כאן, ולרובם אין בו תגיות
אלרגנים. המקור האיכותי הוא אתרי היצרנים, ושם החסם הוא מניית המוצרים
ולא קריאתם. ראו למטה.

## המבנה

```
CONTEXT.md              מילון המונחים של התחום
docs/adr/               חמש החלטות ארכיטקטורה שקשה לחזור מהן
pipeline/               צינור האיסוף (Python)
  domain/               טקסונומיה, קביעות, הכרעה, פירוק, סינון
  ingredients/          מיפוי רכיבים לאלרגנים, מתוחזק ידנית
  sources/              מתאמי רשתות, יצרנים ו-Open Food Facts
  catalog/              ברקודים, שמות קנוניים, מחלקות, מחזור חיי מוצר
  snapshot/             בניית תמונת המצב שהאפליקציה מורידה
app/                    האפליקציה (Expo / React Native / TypeScript)
```

## הפעלה

```bash
cd pipeline; python -m venv .venv; .\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

בניית קטלוג בלבד, בלי רשת מעבר לקבצי הרשתות:

```bash
cd pipeline; .\.venv\Scripts\python.exe -m allergen_pipeline.build_catalog --stores 5
```

בנייה עם אלרגנים ממה שכבר במטמון, בלי פנייה לרשת:

```bash
cd pipeline; .\.venv\Scripts\python.exe -m allergen_pipeline.build_catalog --stores 5 --allergens --cache-only
```

קריאת דפי יצרן, והעתקת תמונת המצב לאפליקציה:

```bash
cd pipeline; .\.venv\Scripts\python.exe -m allergen_pipeline.fetch_manufacturers; .\.venv\Scripts\python.exe -m allergen_pipeline.publish_snapshot
```

בדיקות:

```bash
cd pipeline; .\.venv\Scripts\python.exe -m pytest -q
```

```bash
cd app; npm install; npm run typecheck; npm test
```

## מה שלמדנו מהרצה מול המקורות האמיתיים

**קבצי שקיפות המחירים אינם מה שהתקנות מרמזות.** שופרסל כותבת
`ManufactureName` ולא `ManufacturerName`, `PriceUpdateTime` ולא
`PriceUpdateDate`, ותאריכים ב-ISO עם T. בלי האליאסים האלה שם היצרן חוזר
ריק בכל השורות והקטלוג נראה תקין למרות שאינו.

**ספרות דבוקות לאותיות הן הכלל ולא היוצא מן הכלל.** "100ג", "32יח",
"5סכיני". בלי הפרדה בנרמול, שום כלל סיווג ושום חיפוש לא מוצאים אותן.

**רשתות המזון מוכרות הרבה דברים שאינם מזון.** שמפו, סכיני גילוח,
טמפונים. הם אינם נמחקים, כי סריקה חייבת תמיד להחזיר תשובה, אבל הם
מסומנים כלא-מזון ואינם מופיעים בעיון לפי מחלקות.

**אתר היצרן אינו דורש דפדפן אוטומטי.** ה-403 שקיבלנו נבע מכותרות דלות
בלבד. עם כותרות של דפדפן אמיתי דף המוצר חוזר 200, ותוכן האקורדיון נמצא
כבר ב-HTML הסטטי.

**Open Food Facts: נקודת הקצה של חיפוש מרובה שבורה למעשה** ומחזירה 503
באופן קבוע, בעוד שנקודת הקצה של מוצר בודד יציבה לחלוטין. ריצה ראשונה עם
שמונה חוטים בלי ויסות עברה פי עשרים את המגבלה, 83 אחוז מהבקשות נכשלו,
והמספרים שהתקבלו היו חסרי משמעות. הצינור מווסת עכשיו לשלושים בקשות
לדקה, נעצר מעצמו כששיעור הכשלים חוצה חמישים אחוז, וממשיך מהמטמון.

## מה לא נבנה, ולמה

**מניית קטלוג היצרנים.** דפי המוצר של אסם נקראים בלי בעיה, אבל דפי
המותג, `sitemap.xml` ו-`robots.txt` מחזירים 403. אפשר לקרוא דף שכתובתו
ידועה, אך לא לגלות אילו דפים קיימים. גרסה 1 עובדת מרשימת כתובות
מתוחזקת ידנית של שמונה מוצרים, והיא מוצהרת ככזו ואינה מתחזה לכיסוי.
מניית הקטלוג דורשת דפדפן אוטומטי ונדחתה.

**שאר הרשתות.** רמי לוי, ויקטורי, יוחננוף וחצי חינם מוגדרים בתצורה,
אך המתאם לפורטל המשותף שדורש התחברות לא נבנה. הקטלוג הנוכחי הוא שופרסל
בלבד.

**העשרה מלאה של הקטלוג.** ריצה מלאה בקצב מנומס אורכת שעות, והיא עבודת
רקע מתוזמנת. עד שתרוץ, הכיסוי נשאר כפי שמוצג בטבלה למעלה.

**אחסון תמונות, שרת API, ועיבוד צילומי תווית ממשתמשים.**

## סיכונים פתוחים

- **כיסוי האלרגנים נמוך מכדי שהאפליקציה תהיה שימושית לרוב הקניות.** זו
  לא בעיה טכנית אלא בעיית מקורות, והפתרון הוא מתאמי יצרנים נוספים.
- **אישור בחנויות האפליקציות.** אפליקציית אלרגיות עלולה לקבל דרישות
  ניסוח מאפל ומגוגל.
- **האפליקציה לא הורצה על מכשיר.** הטייפצ'ק והבדיקות עוברים, אך אין
  Android SDK או Xcode על מכונת הפיתוח, ולכן לא נבנתה חבילה ולא נפתח
  מסך אמיתי.
